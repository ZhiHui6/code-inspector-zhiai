## 适用范围

加载条件包括 `.c`、`.h`、`.cc`、`.cpp`、`.hpp`、CMake、Make、Meson 或 Visual Studio 项目。先区分 C/C++ 标准、编译器、平台和构建配置。

## 内存与未定义行为

- `CPP-LIFE-001`：检查 use-after-free、double free、悬空引用、越界、未初始化读取和所有权不清。
- `CPP-RAII-001`：C++ 优先核对 RAII、智能指针、异常安全和容器边界；C 项目检查显式 cleanup 的所有返回路径。
- `CPP-UB-001`：检查有符号溢出、移位、对齐、strict aliasing、格式化和整数/指针转换。
- `CPP-FFI-001`：检查 ABI、结构体布局、字符串终止、调用约定和跨语言资源释放。
- `CPP-HEADER-001`：检查头文件是否使用 include guards 或 `#pragma once`、是否暴露实现细节、是否存在重复包含或宏污染风险；结合构建配置判断。

## 边界与并发

- `CPP-INPUT-001`：追踪长度、索引、文件、网络和格式化输入到内存/命令/API sink。
- `CPP-CON-001`：检查数据竞争、锁顺序、原子内存序、线程生命周期和回调注销。
- `CPP-EXCEPTION-001`：检查异常安全等级、错误码和析构函数行为；不要要求所有项目统一使用异常。

## 构建与验证

优先使用项目构建命令、编译器警告、clang-tidy、静态分析和 Sanitizer。不要在没有复现或工具证据时把性能猜测写成缺陷；保留平台/编译选项差异。
